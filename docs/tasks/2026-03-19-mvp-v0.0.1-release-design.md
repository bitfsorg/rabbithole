# MVP v0.0.1 Release Design

**Date**: 2026-03-19
**Status**: Approved (reviewed 2026-03-19)

## Product Definition

BitFS v0.0.1 is a decentralized encrypted file system CLI tool targeting early technical users. Users install from source and can perform encrypted file storage, directory management, content pricing/selling, and paid downloads on BSV testnet/mainnet.

## Target Audience

Early real users who can install from source (`go install` / `go build`). Not a demo — must be stable and usable on mainnet.

## Pre-Release Fixes

### Fix 1: H-1 — acl_ref Semantic Unification

**Problem**: TLV comment says `acl_ref` is "group sig pubkey hash OR ACL rule TxID"; ACL implementation section mandates pubkey-only (permanent node identity, auto-resolves to latest version).

**Fix**: Unify to **pubkey semantics**. Remove "or TxID" from TLV comment. Rationale: pubkey as permanent node identity aligns with Metanet DAG design philosophy; TxID is version-specific and unsuitable for ACL references.

**Scope**: 1-2 documentation edits in `docs/design/bitfs/2-SystemDesign.zh.md`. Also review `libbitfs-go` for any `acl_ref` parsing code that handles both pubkey and TxID formats — align if needed.

### Fix 2: H-2 — Invoice State Persistence

**Problem**: System design promises persistence to `~/.bitfs/invoices/`; the detailed design still says "stored in `Server.invoices map`"; the `POST /_bitfs/pay` API doc still says "accepts empty body" despite the implementation requiring a hex-encoded raw transaction.

**Current state**: Persistence infrastructure partially exists (`daemon.go:510-575`: `persistInvoice()`, `loadInvoice()`, `recoverPersistedInvoices()`, `SetInvoiceDir()`), but has three gaps:

1. **Persist-on-create missing**: `persistInvoice` is only called on payment finalization, not on invoice creation. Unpaid invoices are never written to disk.
2. **Eviction doesn't clean disk**: `evictExpiredInvoices()` only calls `delete(d.invoices, id)` — no `os.Remove()` for the `.json` file. Disk files accumulate forever.
3. **Recovery skips unpaid**: `recoverPersistedInvoices()` only recovers paid invoices (`if inv.Paid`), silently discarding unpaid-but-unexpired invoices on restart.

**Fix**:
- Add `persistInvoice` call on invoice creation
- Add `os.Remove` in eviction logic for expired invoice files
- Expand recovery to load all unexpired invoices (not just paid ones)
- Update detailed design: remove "stored in map" text, update `POST /_bitfs/pay` body description to match actual implementation (hex-encoded raw transaction required)

**Not doing**:
- No BoltDB/SQLite (overkill for low invoice volume)
- No on-chain settlement records (out of v0.0.1 scope)

**Scope**: ~50-100 LOC code fixes in `bitfs/internal/daemon/` + design doc updates + tests.

### Fix 3: M-1 — Permission Decision Matrix

**Problem**: `acl_ref`, `access` field, and owner fallback have no unified priority rule for conflict scenarios.

**Fix**: Add unified permission decision table to detailed design.

Decision rules:
1. **Write operations**: owner-only (application-layer enforcement, no on-chain constraint in v0.0.1)
2. **Read operations decision chain**:
   - a. Has `acl_ref` → resolve ACL node → decide per ACL rules
   - b. `acl_ref` resolution fails (node missing/corrupted) → **fail-closed**, deny access
   - c. No `acl_ref` → decide by `access` field:
     - FREE → allow
     - PAID → require HTLC payment
     - PRIVATE → require Method 42 handshake (owner or authorized party only)
   - d. No `acl_ref` and no `access` → owner-only

**Also fix**:
- Remove stale `share_list` priority chain text from `3-DetailedDesign.zh.md` (line ~3151: `优先级: acl_ref > share_list > 默认 owner 权限`) — contradicts the new matrix
- Acknowledge that `libbitfs-go/metanet/` parser still accepts `share_list` field for backward compatibility; no code removal in v0.0.1

**Not doing**:
- No `share_list` enforcement (ACL sufficient for v0.0.1; share_list deferred)
- No covenant on-chain enforcement

**Scope**: Design doc addition + stale reference cleanup + daemon code review for alignment.
