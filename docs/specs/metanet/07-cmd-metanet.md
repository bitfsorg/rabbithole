# 模块规格说明：cmd/metanet

## 目的

`metanet` CLI 是 Metanet Node 运营者的命令行工具。它管理 Metanet Node 的完整生命周期：初始化、守护进程控制、状态监控、存储合约管理、对等节点连接和合并挖矿配置。

该 CLI 是与 `bitfs`（面向用户的文件系统工具）独立的二进制文件。它共享核心 Go 库（`github.com/tongxiaofeng/bitfs`）的 Method 42 加密、Metanet DAG 解析、SPV 和交易构造功能。`metanet` 二进制文件面向希望通过缓存和提供内容来获取收入的 CDN 节点运营者。

## 公开 API

### 命令

```
metanet init [--datadir <path>] [--testnet]
    初始化新的 Metanet Node。
    - 生成节点密钥对（secp256k1）
    - 创建数据目录结构
    - 生成默认配置文件
    - 输出节点公钥（身份标识）

metanet start [--mine] [--port <port>] [--datadir <path>]
    启动 Metanet Node 守护进程。
    - 连接到 Metanet Chain 对等节点
    - 开始参与覆盖网络
    - 开始提供下载计费内容请求服务
    - 如果指定 --mine：启用合并挖矿
    - 在前台运行（使用 systemd/launchd 实现后台运行）

metanet stop [--datadir <path>]
    优雅地停止 Metanet Node 守护进程。
    - 向覆盖网络对等节点宣布离开
    - 协作关闭活跃的支付通道
    - 将状态持久化到磁盘

metanet status [--json]
    显示节点状态。
    - 节点公钥和端点
    - 运行时间
    - 已连接对等节点数
    - 缓存内容（数量、总大小）
    - 活跃存储合约
    - 收入汇总（来自下载计费的 BSV、来自合约/挖矿的 MNT）
    - 挖矿状态（如已启用）

metanet contracts [--active|--expired|--all] [--json]
    列出存储合约。
    - 合约 ID（TxID）
    - 所有者公钥
    - 数据大小、分片数
    - 已完成周期 / 总周期
    - 下一个证明截止时间
    - 已获收入 / 剩余收入

metanet peers [--json]
    列出已连接的对等节点。
    - 对等节点公钥
    - 端点
    - 连接持续时间
    - 数据交换量

metanet mine [--enable|--disable] [--threads <n>] [--parent-rpc <url>]
    配置合并挖矿。
    - 启用/禁用挖矿
    - 设置 CPU 线程数
    - 配置父链（BTC/BSV）RPC 端点用于 coinbase 嵌入
    - 显示当前挖矿统计（算力、已发现区块）
```

### 配置文件

```toml
# ~/.metanet/config.toml (generated by 'metanet init')

[node]
# Node identity (auto-generated)
pubkey = "<hex-encoded compressed public key>"
datadir = "~/.metanet"
port = 8402
network = "mainnet"  # or "testnet"

[storage]
# Maximum storage capacity for cached content
max_cache_size = "100GB"
# Maximum storage for archive contracts
max_archive_size = "1TB"
# Minimum download revenue rate to cache content (sat/KB/day)
min_revenue_rate = 1

[mining]
enabled = false
threads = 1
parent_rpc = ""  # BTC/BSV node RPC for coinbase embedding

[overlay]
# Bootstrap peers
bootstrap_peers = [
    "seed1.metanet.org:8402",
    "seed2.metanet.org:8402",
]
# Heartbeat interval in seconds
heartbeat_interval = 300
# Maximum peer age before pruning (seconds)
max_peer_age = 3600

[payment]
# BSV channel parameters
bsv_min_deposit = 10000
bsv_max_duration = 144
# MNT channel parameters
mnt_min_deposit = 10000
mnt_max_duration = 1008  # ~1 week
```

### 退出码

| 代码 | 含义 |
|------|---------|
| 0 | 成功 |
| 1 | 一般错误 |
| 2 | 无效参数 |
| 3 | 配置错误 |
| 4 | 节点未初始化（请先运行 `metanet init`） |
| 5 | 守护进程未运行（用于 `stop`、`status`） |
| 6 | 守护进程已在运行（用于 `start`） |
| 7 | 网络错误 |

## 依赖

- `internal/chain` -- 链参数、区块类型
- `internal/mining` -- 合并挖矿
- `internal/contract` -- 存储合约管理
- `internal/proof` -- 存储证明生成
- `internal/payment` -- 支付通道管理
- `internal/overlay` -- 对等节点发现与路由
- `internal/config` -- 配置管理
- `github.com/tongxiaofeng/bitfs` -- 共享库（method42、metanet、spv、tx）
- `github.com/bsv-blockchain/go-sdk` -- BSV 操作

## 数据结构

### 数据目录布局

```
~/.metanet/
├── config.toml          # 节点配置
├── node.key             # 节点私钥（加密存储）
├── chain/               # Metanet Chain 数据
│   ├── blocks/          # 区块存储
│   └── state/           # UTXO 集、链状态
├── cache/               # 缓存的热点内容
│   └── <content_hash>/  # 单个内容文件
├── archive/             # 归档合约数据
│   └── <contract_txid>/ # 按合约存储的数据
├── channels/            # 支付通道状态
│   ├── bsv/             # BSV 通道
│   └── mnt/             # MNT 通道
├── peers/               # 对等节点数据库
└── logs/                # 日志文件
```

## 错误处理

| 错误 | 用户提示信息 |
|-------|-------------|
| 节点未初始化 | "Error: node not initialized. Run 'metanet init' first." |
| 守护进程已在运行 | "Error: daemon already running (PID <pid>)." |
| 守护进程未运行 | "Error: daemon not running." |
| 配置无效 | "Error: invalid configuration: <details>" |
| 端口被占用 | "Error: port <port> already in use." |
| 密钥文件缺失 | "Error: node key file not found at <path>." |
| 网络不可达 | "Error: cannot reach any bootstrap peers." |

## 安全考量

1. **密钥保护**：节点私钥（`node.key`）在静态存储时使用密码短语加密。CLI 在 `start` 时提示输入密码（或从 `METANET_PASSPHRASE` 环境变量读取，用于自动化部署）。
2. **默认无远程访问**：守护进程仅在配置端口上监听覆盖网络和下载计费流量。除非显式配置，否则不暴露管理 API。
3. **通道状态持久化**：每次更新后支付通道状态都会持久化到磁盘，防止崩溃时丢失资金。
4. **优雅关闭**：`metanet stop` 会协作关闭支付通道并宣布离开，防止对手方混乱。
5. **测试网隔离**：测试网模式使用独立的数据目录和引导对等节点，防止主网污染。
6. **JSON 输出**：`--json` 标志提供机器可读的输出，适用于监控系统和自动化，遵循 Agent-first 设计原则。
