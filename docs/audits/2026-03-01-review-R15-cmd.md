## Findings

### CRITICAL

无。

### HIGH

**H-1: `bmget` 路径遍历 — 恶意 daemon 可写入任意文件**

`cmd/bmget/main.go` L230-231:
```go
childPath := path.Join(uriPath, childEntry.Name)
localPath := filepath.Join(localDir, childEntry.Name)
```

`childEntry.Name` 来自 daemon HTTP 响应，无任何清理。恶意 daemon 返回 `Name: "../../.ssh/authorized_keys"` 可写入用户主目录外的任意位置。`filepath.Join` 会清理路径但不会阻止向上遍历。

对比 `cmd/bitfs/cmd_mget.go` 正确验证 `strings.Contains(child.Name, "..")`。

**建议**: 添加与 `cmd_mget.go` 一致的 name 验证：拒绝含 `..`、`/`、`\` 的条目名。

**H-2: 私钥通过 CLI flag 暴露**

`cmd/bcat/main.go` L39、`cmd/bget/main.go` L41、`cmd/bmget/main.go` L41:
```go
walletKey := fs.String("wallet-key", "", "hex-encoded buyer private key (32 bytes)")
```

三个 b-tools 均接受 32 字节 hex 私钥作为命令行参数。可通过 `ps aux`、`/proc/<pid>/cmdline`、shell 历史文件、系统审计日志泄露。

**建议**: 使用 `--wallet-key-file <path>` 或环境变量 `BITFS_WALLET_KEY` 替代。

**H-3: 钱包密码作为 string slice 传递后残留内存**

`cmd/bitfs/cmd_wallet.go` L211:
```go
code := runWalletFund([]string{"--datadir", *dataDir, "--password", pass})
zeroString(&pass)
```

`zeroString(&pass)` 清零了 `pass` 变量，但 `pass` 已被复制到 `[]string` slice 中作为独立的堆分配字符串。该副本不会被清零，在 GC 回收前保留在内存中（crash dump、swap 文件中可见）。

**建议**: 将 password 作为 `*string` 或通过其他机制传递，确保所有副本被清零。

### MEDIUM

**M-1: `wallet.MainNet` 硬编码 — 忽略配置的网络**

`cmd/bitfs/cmd_wallet.go` L255 (`runWalletShow`) 和 L433 (`loadWalletFromDataDir`):
```go
w, err := wallet.NewWallet(seed, &wallet.MainNet)
```

`wallet init` 正确接受 `--network` 并保存到配置。但 `runWalletShow` 和 `loadWalletFromDataDir` 无条件使用 `wallet.MainNet`。`loadWalletFromDataDir` 被 `cmd_vault.go` 的 4 个调用点使用（put、mkdir、rm 等），导致 regtest/testnet 钱包在所有文件系统命令中使用错误的 HD 派生参数。

**建议**: 从配置文件读取网络设置。

**M-2: Shell `sales` 命令硬编码 `localhost:8080`**

`cmd/bitfs/cmd_shell.go` L480-481:
```go
daemonURL := "http://localhost:8080" // default daemon port
cl := client.New(daemonURL)
```

`shellCtx` 不携带 daemon URL。其他 shell 命令通过 `ctx.eng`（vault）访问。`sales` 是唯一直接创建 client 的命令，绕过了 `--host` flag。非默认端口的 daemon 上此命令永远失败。

**建议**: 将 daemon URL 添加到 `shellCtx`。

**M-3: Shell `cat --force` 位置参数解析脆弱**

`cmd/bitfs/cmd_shell.go` L318:
```go
force := len(args) > 1 && args[1] == "--force"
```

仅检查 `args[1]`。`cat <path> --force` 工作正常，但 `cat --force <path>`（标准 Unix 风格）不会设置 `force=true`，而是将 `--force` 作为路径使用。无错误提示。

**建议**: 使用 `flag.FlagSet` 或至少扫描所有 args 查找 flag。

**M-4: RPC 密码通过 CLI 暴露**

`cmd/bitfs/cmd_wallet.go`: `--rpcpass` 以明文出现在进程参数列表中。与 H-2 同类问题。

**M-5: Shell 历史可能泄露敏感操作**

Shell REPL 的命令历史（如 `sell --price`、`encrypt`）可能包含敏感参数。无自动清理机制。

### LOW

**L-1: `zeroString` 在 Go 1.20+ 不保证有效**: 编译器可能优化掉对即将丢弃的变量的清零操作。

**L-2: `cmd/bitfs` PID 文件使用 SIGTERM 信号**: `cmd_daemon.go` — 正确实现，无问题。

**L-3: `rm` 命令缺少 `-r` 递归删除选项**: Shell 中 `rm` 仅删除单文件。

**L-4: `sell` 命令缺少 `--recursive` 选项**: 无法批量设置目录下所有文件的价格。

**L-5: UTXO 扫描范围 off-by-one**: `NextReceiveIndex + 10` 是否应包含 `+10` 本身。

**L-6: `formatSize` 在 bls 和 bstat 中重复实现**: 应提取为共享辅助函数。

### SUGGESTIONS

**S-1.** 统一 b-tools 的 flag 解析模式。当前 bcat/bget/bmget 各自实现，代码重复。

**S-2.** 添加 `--json` 输出模式到所有 b-tools（目前仅 bcat/bget 支持）。

**S-3.** Shell REPL 应支持 readline/history 持久化（已有 liner 依赖但未完全利用）。

## Code Quality Assessment

**优点**:
1. 711 个测试，测试代码量 2.2x 源代码
2. 一致的两层委托模式（解析 flags → 打开 vault → 调用单个 vault 方法 → 打印结果）
3. `cmd_mget.go` 正确的路径遍历防护（`bmget` 应参照此实现）
4. Exit code 设计良好（`exit.go` — ErrNotFound→1, ErrPaymentRequired→2, etc.）
5. b-tools 共享 `buyer/` 包的错误处理模式

**不足**:
1. `bmget` 路径遍历漏洞
2. 三个工具通过 CLI 暴露私钥
3. 网络配置硬编码 MainNet
4. Shell 命令解析不一致（flag vs 位置参数）
5. `sales` 命令硬编码端口

## Summary

cmd/ 是 BitFS 最大的代码目录，711 个测试覆盖良好。架构清晰 — CLI 层薄壳，所有业务逻辑委托给 vault。

**必须修复**:
- H-1: `bmget` 路径遍历 — 安全漏洞，一行验证修复
- H-2: 私钥 CLI 暴露 — 改用文件或环境变量

**应该修复**:
- M-1: MainNet 硬编码 — 破坏 testnet/regtest 工作流
- M-2: Shell sales 硬编码端口
