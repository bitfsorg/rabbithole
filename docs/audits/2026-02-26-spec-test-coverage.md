### 1.2 逐包缺口详情

#### method42 (95/100) — 几乎完美

所有 8 个哨兵错误均有显式测试。有 `coverage_supplement_test.go` 文档化 13 个审计缺口并已修复。有 fuzz 测试。

**残余缺口** (低优先级):
- HKDF 最大长度输入边界

---

#### tx (90/100) — 非常好

15 个 spec 定义的缺口已通过 supplement 测试覆盖。签名测试 (`sign_test.go`) 和批量操作 (`batch_test.go`) 完整。

**残余缺口**:
- `ParseOPReturnData` 尾部垃圾数据处理
- `EstimateTxSize`/`EstimateFee` 极端 payload (>1MB)
- 多输入交易构建 (spec 暗示多 UTXO，但测试仅用单个 fee UTXO)

---

#### wallet (80/100) — 良好

核心功能 (助记词、种子加密、密钥派生、Vault CRUD) 完整覆盖。

**缺口**:

| Vault 名称冲突处理 | LOW | ErrVaultExists 弱测试 |
| 空 vs 长 passphrase | LOW | 未测试 passphrase 鲁棒性 |
| 硬化 vs 非硬化派生差异 | LOW | 仅部分覆盖 |

### 2.3 集成测试中的 CLI 端到端缺口

**关键发现**: `bitfs/integration/` 中的 275 个集成测试全部通过 Go API 调用测试，**没有任何测试通过 CLI 二进制调用** (exec + 检查 stdout/stderr/exit code)。

这意味着:
- 命令行参数解析错误不会被集成测试捕获
- 退出码在集成级别未验证
- stdin/stdout 管道行为未验证
- 错误消息格式在端到端级别未验证

### 4.2 集成测试关键缺口

#### 最大缺口 1: CLI 端到端 (0/35 = 0%)

**完全缺失**: 无任何测试通过调用 `bitfs` 或 `b*` 二进制文件验证 CLI 行为。

应添加的测试:
- `bitfs put` + `bcat` 端到端
- `bitfs mkdir` + `bls` 端到端
- `bitfs sell` + `bget --buy` 端到端
- 退出码验证
- JSON 输出格式验证

#### 最大缺口 2: Daemon API 集成 (15/40 = 38%)

已覆盖: 健康检查、内容协商、BSV Alias、CORS
**缺失**:
- Method 42 握手完整协议流程 (集成级)
- 文件实际服务 (GET /path/to/file)
- 目录元数据检索
- 请求超时处理
- 内容缓存验证
- Range 请求 (HTTP 206)

#### 最大缺口 3: SPV 集成 (20/30 = 67%)

已覆盖: Merkle 证明、头部链验证
**缺失**:
- 缺失头部时的重试逻辑
- 错误区块哈希引用
- PoW 验证 (目标值检查)
- 重组检测
- 批量头部验证 (100+)

#### 较小缺口 4: URI 解析集成 (25/35 = 71%)

**缺失**:
- Paymail PKI 端点发现
- DNS TXT 记录解析
- 网络特定端点选择
- 回退解析链 (PubKey → DNSLink → Paymail)

#### 较小缺口 5: 文件系统集成 (40/50 = 80%)

**缺失**:
- 目录 Merkle root 计算
- 深层符号链接链 (3+ 级)
- 原子目录更新 (并发修改)
- 批量删除操作
- 目录复制操作
