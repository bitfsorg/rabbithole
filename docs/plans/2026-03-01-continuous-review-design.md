# 持续全面审查计划

日期: 2026-03-01

## 目标

对已完成代码逐模块进行深度审查，覆盖安全、一致性、代码质量三个维度。

## 方法

**方案 A — 按模块纵切**：逐包深入审查，每包一轮，按风险优先级排序。

### 每轮审查流程

1. 读取该包全部源码和测试
2. 对照 `docs/specs/` 对应 spec 检查一致性
3. 从安全、正确性、代码质量三个维度审查
4. 生成报告写入 `docs/audits/2026-03-01-review-R{N}-{package}.md`
5. 对话中汇报摘要

### 审查维度

每个包覆盖以下三个维度：

- **安全**: 输入验证、边界检查、加密正确性、信息泄露、注入风险
- **一致性**: spec vs 实现偏差、API 合约、错误码
- **代码质量**: 错误处理、命名、复杂度、可测试性、边界条件

### 审查顺序（按风险优先级）

| 轮次 | 包 | 理由 |
|------|------|------|
| R01 | method42 | 加密核心，安全最高优先级 |
| R02 | x402 | 支付协议，资金安全 |
| R03 | spv | 链验证，已知有 P0 问题 |
| R04 | wallet | 密钥管理，资金安全 |
| R05 | tx | 交易构建，链上不可逆 |
| R06 | metanet | DAG 核心数据结构 |
| R07 | storage | 内容寻址存储 |
| R08 | network | 网络通信层 |
| R09 | paymail | 身份解析协议 |
| R10 | revshare | 收入分配 |
| R11 | vault | 统一状态管理 |
| R12+ | bitfs 应用层 | daemon, CLI, b*tools |

```markdown
- 包路径: ...
- 代码行数: ...
- 测试数量: ...
- 对应 Spec: ...

## 发现

### 严重 (CRITICAL)
### 高 (HIGH)
### 中 (MEDIUM)
### 低 (LOW)
### 建议 (SUGGESTION)

spec vs 实现偏差列表

## 代码质量
风格、命名、复杂度等
```

## 输出

所有报告写入 `docs/audits/`，命名格式 `2026-03-01-review-R{NN}-{package}.md`。
