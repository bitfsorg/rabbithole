# Module Specification: cmd/metanet

## PURPOSE

The `metanet` CLI is the Metanet Node operator's command-line tool. It manages the lifecycle of a Metanet Node: initialization, daemon control, status monitoring, storage contract management, peer connectivity, and merged mining configuration.

The CLI is a separate binary from `bitfs` (the user-facing filesystem tool). It shares the core Go library (`github.com/tongxiaofeng/bitfs`) for Method 42 encryption, Metanet DAG parsing, SPV, and transaction construction. The `metanet` binary is designed for CDN node operators who want to earn revenue by caching and serving content.

## PUBLIC API

### Commands

```
metanet init [--datadir <path>] [--testnet]
    Initialize a new Metanet Node.
    - Generates node keypair (secp256k1)
    - Creates data directory structure
    - Generates default configuration file
    - Outputs node public key (identity)

metanet start [--mine] [--port <port>] [--datadir <path>]
    Start the Metanet Node daemon.
    - Connects to Metanet Chain peers
    - Starts overlay network participation
    - Begins serving x402 content requests
    - If --mine: enables merged mining
    - Runs in foreground (use systemd/launchd for background)

metanet stop [--datadir <path>]
    Gracefully stop the Metanet Node daemon.
    - Announces departure to overlay peers
    - Closes active payment channels cooperatively
    - Persists state to disk

metanet status [--json]
    Show node status.
    - Node public key and endpoint
    - Uptime
    - Connected peers count
    - Cached content (count, total size)
    - Active storage contracts
    - Revenue summary (BSV from x402, MNT from contracts/mining)
    - Mining status (if enabled)

metanet contracts [--active|--expired|--all] [--json]
    List storage contracts.
    - Contract ID (TxID)
    - Owner public key
    - Data size, chunk count
    - Periods completed / total
    - Next proof deadline
    - Revenue earned / remaining

metanet peers [--json]
    List connected peers.
    - Peer public key
    - Endpoint
    - Connection duration
    - Data exchanged

metanet mine [--enable|--disable] [--threads <n>] [--parent-rpc <url>]
    Configure merged mining.
    - Enable/disable mining
    - Set CPU thread count
    - Configure parent chain (BTC/BSV) RPC endpoint for coinbase embedding
    - Show current mining statistics (hashrate, blocks found)
```

### Configuration File

```toml
# ~/.metanet/config.toml (generated by 'metanet init')

[node]
# Node identity (auto-generated)
pubkey = "<hex-encoded compressed public key>"
datadir = "~/.metanet"
port = 8402
network = "mainnet"  # or "testnet"

[storage]
# Maximum storage capacity for cached content
max_cache_size = "100GB"
# Maximum storage for archive contracts
max_archive_size = "1TB"
# Minimum x402 revenue rate to cache content (sat/KB/day)
min_revenue_rate = 1

[mining]
enabled = false
threads = 1
parent_rpc = ""  # BTC/BSV node RPC for coinbase embedding

[overlay]
# Bootstrap peers
bootstrap_peers = [
    "seed1.metanet.org:8402",
    "seed2.metanet.org:8402",
]
# Heartbeat interval in seconds
heartbeat_interval = 300
# Maximum peer age before pruning (seconds)
max_peer_age = 3600

[payment]
# BSV channel parameters
bsv_min_deposit = 10000
bsv_max_duration = 144
# MNT channel parameters
mnt_min_deposit = 10000
mnt_max_duration = 1008  # ~1 week
```

### Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | General error |
| 2 | Invalid arguments |
| 3 | Configuration error |
| 4 | Node not initialized (run `metanet init` first) |
| 5 | Daemon not running (for `stop`, `status`) |
| 6 | Daemon already running (for `start`) |
| 7 | Network error |

## DEPENDENCIES

- `internal/chain` -- Chain parameters, block types
- `internal/mining` -- Merged mining
- `internal/contract` -- Storage contract management
- `internal/proof` -- Storage proof generation
- `internal/payment` -- Payment channel management
- `internal/overlay` -- Peer discovery and routing
- `internal/config` -- Configuration management
- `github.com/tongxiaofeng/bitfs` -- Shared library (method42, metanet, spv, tx)
- `github.com/bsv-blockchain/go-sdk` -- BSV operations

## DATA STRUCTURES

### Data Directory Layout

```
~/.metanet/
├── config.toml          # Node configuration
├── node.key             # Node private key (encrypted)
├── chain/               # Metanet Chain data
│   ├── blocks/          # Block storage
│   └── state/           # UTXO set, chain state
├── cache/               # Cached hot content
│   └── <content_hash>/  # Individual content files
├── archive/             # Archive contract data
│   └── <contract_txid>/ # Per-contract data
├── channels/            # Payment channel state
│   ├── bsv/             # BSV channels
│   └── mnt/             # MNT channels
├── peers/               # Peer database
└── logs/                # Log files
```

## ERROR HANDLING

| Error | User Message |
|-------|-------------|
| Node not initialized | "Error: node not initialized. Run 'metanet init' first." |
| Daemon already running | "Error: daemon already running (PID <pid>)." |
| Daemon not running | "Error: daemon not running." |
| Invalid config | "Error: invalid configuration: <details>" |
| Port in use | "Error: port <port> already in use." |
| Key file missing | "Error: node key file not found at <path>." |
| Network unreachable | "Error: cannot reach any bootstrap peers." |

## SECURITY CONSIDERATIONS

1. **Key protection**: The node private key (`node.key`) is encrypted at rest using a passphrase. The CLI prompts for the passphrase on `start` (or reads from `METANET_PASSPHRASE` environment variable for automated deployments).
2. **No remote access by default**: The daemon only listens on the configured port for overlay and x402 traffic. No admin API is exposed unless explicitly configured.
3. **Channel state persistence**: Payment channel states are persisted to disk after every update to prevent loss of funds on crash.
4. **Graceful shutdown**: `metanet stop` cooperatively closes payment channels and announces departure, preventing counterparty confusion.
5. **Testnet isolation**: Testnet mode uses separate data directories and bootstrap peers to prevent mainnet contamination.
6. **JSON output**: The `--json` flag provides machine-readable output for monitoring systems and automation, following the Agent-first design principle.
