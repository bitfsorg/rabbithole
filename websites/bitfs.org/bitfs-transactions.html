HTLC Payment 1 — Lock (Client) client locks payment funds · x402 protocol step 1

Inputs

[0] HTLC Lock Output

value payment_amount
HTLC Redeem Script
OP_IF // preimage branch
OP_SHA256 <payment_hash> OP_EQUALVERIFY
OP_DUP OP_HASH160 <H(P_server)>
OP_EQUALVERIFY OP_CHECKSIG
OP_ELSE // timeout branch
<cltv_height> OP_CHECKLOCKTIMEVERIFY OP_DROP
OP_DUP OP_HASH160 <H(P_client)>
OP_EQUALVERIFY OP_CHECKSIG
OP_ENDIF
[1] Change
script P2PKH(D_client)
value remainder
x402 Lock: client proves payment intent to server. payment_hash = SHA256(preimage), preimage revealed by server when delivering content. cltv_height = current block height + delta (e.g. +6 blocks). HTLC txid submitted as 402 Payment Header to server.

x402 Claim: after delivering content, server broadcasts this transaction revealing preimage to collect funds. preimage also serves as derivation material for content decryption key (Method 42: aes_key = HKDF(ECDH(D_node, P_client).x, keyHash)). Must broadcast before cltv_height block.

Timeout refund: if server does not broadcast Claim before cltv_height block, client broadcasts this Refund tx to reclaim funds. tx.nLockTime must be >= cltv_height, input nSequence must be < 0xFFFFFFFF (use 0xFFFFFFFE). Standard CLTV usage per BIP 65.
