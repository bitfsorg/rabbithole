# Module Specification: internal/x402

## PURPOSE

x402 payment protocol implementation for BitFS. Handles HTTP 402 Payment Required responses with structured headers (X-Price, X-Price-Per-KB, X-Invoice-Id, etc.), content negotiation for different client types (human, browser agent, CLI agent), and HTLC atomic swap integration for content purchases.

Design references: ConceptDesign #9, #20, #86; SystemDesign section 11, 13; DetailedDesign section 11-B, 13-B.

## PUBLIC API

### Types

```go
// Invoice represents a payment request for content access.
type Invoice struct {
    ID          string `json:"id"`
    Price       uint64 `json:"price"`         // Total price in satoshis
    PricePerKB  uint64 `json:"price_per_kb"`  // Unit price
    FileSize    uint64 `json:"file_size"`     // Content size in bytes
    PaymentAddr string `json:"payment_addr"`  // BSV address for payment
    Expiry      int64  `json:"expiry"`        // Unix timestamp
    KeyHash     []byte `json:"key_hash"`      // Content key hash
    CapsuleHash []byte `json:"capsule_hash"`  // SHA256(ECDH capsule) for HTLC
}

// PaymentHeaders holds the x402 HTTP headers.
type PaymentHeaders struct {
    Price      uint64
    PricePerKB uint64
    FileSize   uint64
    InvoiceID  string
    Expiry     int64
}

// PaymentProof represents a submitted payment for verification.
type PaymentProof struct {
    RawTx       []byte `json:"raw_tx"`       // Serialized BSV transaction
    MerkleProof []byte `json:"merkle_proof"` // Optional Merkle proof
}

// HTLCParams holds parameters for creating an HTLC transaction.
type HTLCParams struct {
    BuyerPubKey  []byte // Buyer's compressed public key
    SellerAddr   []byte // Seller's P2PKH address (20 bytes)
    CapsuleHash  []byte // SHA256(capsule), 32 bytes
    Amount       uint64 // Payment amount in satoshis
    Timeout      uint32 // Timeout in blocks (default 144 = ~24 hours)
}
```

### Functions

```go
// CalculatePrice computes the total price for content.
// total = ceil(pricePerKB * fileSize / 1024)
func CalculatePrice(pricePerKB, fileSize uint64) uint64

// NewInvoice creates a new payment invoice.
func NewInvoice(pricePerKB, fileSize uint64, paymentAddr string, capsuleHash []byte, ttlSeconds int64) *Invoice

// SetPaymentHeaders sets x402 headers on an HTTP response.
func SetPaymentHeaders(w http.ResponseWriter, headers *PaymentHeaders)

// ParsePaymentHeaders extracts x402 headers from an HTTP response.
func ParsePaymentHeaders(resp *http.Response) (*PaymentHeaders, error)

// VerifyPayment verifies that a submitted transaction pays the required invoice.
//   1. Deserialize raw_tx
//   2. Find output matching invoice amount and address
//   3. Verify tx in mempool or has valid Merkle proof
func VerifyPayment(proof *PaymentProof, invoice *Invoice) error

// BuildHTLC constructs an HTLC locking script:
//   IF SHA256(preimage) == capsule_hash AND Sig(seller) THEN seller claims
//   ELSE IF timeout expired AND Sig(buyer) THEN buyer refunds
func BuildHTLC(params *HTLCParams) ([]byte, error)

// ParseHTLCPreimage extracts the capsule (preimage) from a spent HTLC input.
func ParseHTLCPreimage(spendingTx []byte) ([]byte, error)
```

## DATA STRUCTURES

### x402 HTTP Headers
```
HTTP/1.1 402 Payment Required
X-Price: 500
X-Price-Per-KB: 50
X-File-Size: 10240
X-Invoice-Id: abc123
X-Expiry: 1708000000
```

### HTLC Script
```
OP_IF
  OP_SHA256 <capsule_hash> OP_EQUALVERIFY
  <seller_pubkey> OP_CHECKSIG
OP_ELSE
  <timeout> OP_CHECKLOCKTIMEVERIFY OP_DROP
  <buyer_pubkey> OP_CHECKSIG
OP_ENDIF
```

## ERROR HANDLING

| Error | Condition |
|-------|-----------|
| `ErrInvoiceExpired` | Invoice has passed its expiry time |
| `ErrInsufficientPayment` | Transaction output amount < invoice price |
| `ErrPaymentAddrMismatch` | Transaction output address != invoice address |
| `ErrInvalidTx` | Cannot deserialize raw transaction |
| `ErrHTLCBuildFailed` | HTLC script construction failed |
| `ErrNoMatchingOutput` | No transaction output matches invoice |

## SECURITY CONSIDERATIONS

1. **Invoice expiry**: Invoices must have a TTL to prevent stale payment attacks.
2. **HTLC timeout**: Default 144 blocks (~24 hours). Buyer can reclaim funds after timeout if seller fails to reveal capsule.
3. **htlc_tx mandatory**: Design decision #86 -- seller MUST verify the HTLC transaction exists on-chain before revealing the capsule.
4. **Mempool acceptance**: Payment proof can reference mempool transactions (not yet confirmed). Daemon should monitor for double-spend attempts.
